1 Harden Spring Actuator
  • On the application itself, expose only /health endpoints for K8s probes, and optionally exclude subsystem details.
  • Do NOT expose sensitive endpoints such as: /info, /beans, /metrics, /prometheus, /threaddump, /env, /configprops, /sessions, /auditevents, /startup, /shutdown.
  • Keeps the default value of the management.endpoints.web.exposure.include property, which is health.
💡 Note: The following table was created with the assistance of artificial intelligence.
Actuator EndpointPurposes and risks
/healthSafe to expose liveness and readiness probes for K8s when only basic status is exposed. Subsystem health details may reveal infrastructure information.
/infoMay expose application metadata such as app name, version, build info, Git commit details, etc.
/beansExposes detailed bean information in the Spring application context.
/metricsExposes runtime application metrics such as JVM statistics.
/prometheusExposes a large set of application and JVM metrics, including a list of previously invoked endpoints. If these endpoints contain identifiers and require no authentication, a data breach may occur.
/threaddumpExposes JVM thread dump.
/heapdumpExposes JVM heap dump.
/envExposes environment variables (fully sanitized by default).
/configpropsExposes Spring config properties (fully sanitized by default).
/sessionsExposes sensitive user session data and allows attackers to manipulate active sessions.
/auditeventsExposes recorded audit events such as authentication attempts, authorization events, etc.
/startupExposes startup information, including application initialization steps and bean startup details.
/shutdownAllows shutting down the application.

2 Configure cloud API gateway
  • Whitelist explicit API paths by importing the OpenAPI spec file.
  • Avoid wildcard paths (/**).
  • Protect sensitive APIs with OAuth2 authentication at gateway layer if possible.

3 Sanitize error responses
  • Do NOT expose SQL statements, Java class names, or stack traces.
  • Return generic error messages to clients.
  • Log detailed errors internally (console logs or centralized logging) for debugging.

4 Set security headers
  • Configure response headers to prevent iframe embedding and clickjacking attacks:
    • X-Frame-Options: DENY or SAMEORIGIN
    • Content-Security-Policy: frame-ancestors 'none'

5 Adopt Backend-For-Frontend (BFF)
  • Reduces attack surface by limiting direct API exposure.
  • Centralize authentication and security logic in BFF.

6 Use a Web Application and API Protection (WAAP) platform
  • Deploy a WAAP solution such as Akamai, Cloudflare or F5.
  • Benefits:
    • Acts as the outermost protection layer.
    • Detect and block runtime abuse.
    • Provide DDoS scrubbing.
